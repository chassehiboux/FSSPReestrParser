# FSSPReestrParser — согласованная спецификация

## Восстановление авторизации

Ожидание ввода логина и пароля пользователем не расходует время ожидания ответа сервиса. После неверного пароля повторный ввод продолжает тот же процесс без ручного перезапуска. Возврат сервиса на страницу входа при подготовке или выгрузке автоматически повторяет незавершённое задание с восстановлением входа; успешные файлы сохраняются. Повторная подготовка заменяет прежний статус ошибки. Отмена входа останавливает процесс.

## Инструкция при первом запуске

Редакция v0.3.10: повторно перенести все страницы последнего предоставленного Word без собственных дополнений. Фоновая проверка новых выпусков — каждую минуту; найденная версия показывает кнопку и уведомление, текущая операция не прерывается.

Редакция для v0.3.9: использовать новый предоставленный Word без дополнений. В пользовательской инструкции не рассказывать об отключённых дополнительных файлах.

Итоговая редакция Word получена и одобрена пользователем для внедрения и публикации. Источник — `output/user-guide-draft/Инструкция_Реестры_ФССП_для_проверки.docx`, 7 шагов, включая добавленную пользователем авторизацию. Встроенные страницы должны воспроизводить утверждённый текст и изображения со стрелками без редакторских изменений.

Уточнение заказчика: сначала подготовить отдельный редактируемый Word-проект со снимками и стрелками. Внедрение описанного ниже поведения и новый релиз — только после проверки заказчиком и получения его редакции. Программа на этапе подготовки проекта не меняется.

В левом верхнем углу главного окна есть кнопка «Инструкция». Она открывает постраничную инструкцию со снимками интерфейса, стрелками и пояснениями: основная кнопка, папка исходников, выбор файла отказов/извещений, год/месяц и ОК, ход выполнения, открывшаяся папка результата. Есть «Назад», «Далее», на последней странице «Готово» и номер страницы. Снимки используют обезличенные примеры без реальных должников и рабочих выгрузок.

Инструкция автоматически открывается после первоначальной настройки при первом запуске для пользователя Windows. Только «Готово» сохраняет локальную отметку завершения; обновления приложения не сбрасывают её. Закрытие инструкции не закрывает программу. Позже инструкция доступна кнопкой. Также сохраняется отдельная человекочитаемая инструкция для просмотра без приложения.

## Очистка обновлений v0.3.7

Резерв .previous хранится только до подтверждения запуска новой версии, затем удаляется. Временная папка установленного обновления удаляется после завершения процесса установщика. При запуске очищаются оставшиеся папки update-* старше 10 минут и ненужные резерв/next; активная установка защищена именованным mutex. Чужие файлы, настройки и незавершённые выгрузки не очищаются.

## Пустая таблица до старта v0.3.6

Сразу после открытия справа видна полноценная пустая таблица с заголовками столбцов. До начала процесса строки не добавляются. Строки выгрузок и включённых этапов появляются после запуска операции.

## Постоянная ширина v0.3.4

Последнее уточнение для v0.3.5: приложение сразу запускается развёрнутым штатным режимом Windows (максимизированным), а не только растянутым по ширине. Панель статусов постоянно видна справа.

Главное окно сразу открывается широким с постоянной правой областью статусов. Запуск, завершение, сворачивание статусов и раскрытие отдельных операций не меняют размер окна. До запуска в правой области показана подсказка. Обновление использует небольшой прогресс-бар под кнопками слева, не создаёт отдельную операцию.

## Компактное обновление v0.3.4

Скачивание обновления отображается подписью и небольшим прогресс-баром под кнопками в левой части главного окна. Оно не создаёт отдельную операцию и не раскрывает правую панель. При ошибке блок скрывается, сохраняется прежняя возможность продолжить работу.

## Исправление размещения статусов v0.3.3

Статусы встроены справа в то же главное окно. При запуске оно расширяется на доступную ширину монитора, слева сохраняется узкая колонка кнопок. При сворачивании статусов возвращается компактная ширина. Правая таблица использует оставшееся место для подробностей; высота сохраняет место для 20 строк. Отдельные окна статусов не создаются.

## Компактное окно и немедленная запись выгрузок

Отключённые аналитика и реестры по делу не показываются в таблице, нумерация и прогресс учитывают только видимые этапы. При отключённом поиске по делу его счётчик не упоминается в прогрессе и итогах. После успешного создания реестров папка результата открывается автоматически.

Главное окно имеет ширину около 380 пикселей. Статусы встроены справа внутри него; при показе окно расширяется на доступную ширину экрана. Высота рассчитана минимум на 20 строк и ограничена рабочей областью монитора. Сворачивание статусов не прерывает работу. Каждая готовая выгрузка сразу записывается в «Исх.» с повтором записи и сохранением локальной копии при ошибке. После завершения всех заданий остаётся отдельная проверка полного комплекта.

## Единый запуск — 30.10.2026

- Главная кнопка «Выгрузить ОВЗИД и создать реестры»: сразу диалог исходного XLSX, затем календарь месяца/года без выбора папки выгрузки. Прежние две операции доступны в раскрываемом разделе «Отдельные операции».
- Единая нижняя панель показывает все задания выгрузки, проверку записи в папку и этапы создания реестров с прежними цветами. Пустой подтверждённый отбор считается успешным завершением задания.
- Результат — новая папка «Сверка», «Сверка (1)» и далее рядом с исходником. Выгрузки сохраняются внутри неё в «Исх.», без Downloads и даты. При длинном пути физические имена выгрузок сокращаются до номеров; полные условия видны в панели.
- Сначала файлы надёжно сохраняются локально; при сбое сети повторяется запись уже скачанных файлов, а не выгрузка из Пирамиды. До трёх попыток неудачных заданий и записи; успешные задания не повторяются. Перед сверкой проверяются все ожидаемые непустые выгрузки и их контрольные суммы на целевом диске.
- При неполной выгрузке реестры не формируются, появляется возможность продолжить. На том же компьютере сохраняется незавершённый запуск: исходник, снимок параметров, скачанные книги и подтверждённые пустые отборы. Повторный выбор того же неизменённого исходника, периода и настроек продолжает этот запуск; изменённые параметры создают новый комплект. Прежние готовые комплекты не меняются.
- Служебное состояние хранится только в локальной папке программы. «Исх.» содержит только XLSX. Одновременное продолжение одного запуска блокируется файловой блокировкой Windows, освобождаемой при аварийном завершении.
- Выбор исходника использует современный диалог с принудительным открытием сетевой папки, заданной при сборке (`FSSP_REGISTRY_SOURCE_ROOT`). Последний каталог Windows/Downloads не подменяет её; если папка недоступна, показывается ошибка. В авторизации есть подсказка: данные учётной записи Windows, логин без `vostok\`.

## Выгрузка

Профиль Курган: Курган (39), Курган-Восточный (43), Шадринск (40). База Курганская, форма /ovzid/status/all.
Закреплённый основной блок, поле CaseStatusName:
- Направлены на исполнение (нет возбуждения)
- В исполнении (возбуждены ИП)
- ИД возвращенные из ФССП
- Подготовка ИД к возврату в ПУ

12 заданий, до 3 одновременно активных. Освобождение слота после сохранения/ошибки/отмены/подтверждённого отсутствия данных. Сначала подписка на события, потом отправка запроса; подготовка не ждёт скачивания. Контексты и сохранённые прикладные cookies департаментов изолированы. Между ними можно передать только SSO cookies. Нормальный маршрут /login/department не считается истечением входа. При настоящем истечении вход восстанавливается и конкретное задание повторяется один раз, сохраняя слот очереди.

Уточнение 29.10.2026: администратор может задавать от 1 до 20 активных заданий, исходное значение 3 сохраняется. Число 12 — размер основного блока, а не предел параллельности. Первый вход в контекст сразу выбирает нужный департамент; подготовленная вкладка используется первым заданием без закрытия и повторного открытия формы. Избыточный повторный переход на общую форму после выбора департамента убирается, чтобы не прерывать её стартовые запросы. Реальные ошибки страницы не скрываются и не запускают молчаливый перезапуск браузера.
Статусы: очередь, подготовка, формирование, скачивание, сохранён, нет данных, ошибка, отменён. Общий прогресс по заданиям; объём скачивания, если известен. Во время серверного формирования нет выдуманного процента.
Headless включён по умолчанию; переключатель только в админке для тестирования.

## Блоки и справочники

Дополнительные именованные блоки с включением, добавлением/удалением полей, выбором нескольких значений или текстом по типу поля. Независимый режим: сумма значений; связанный: декартово произведение, условия через И. Между блоками объединение заданий без перемножения. Дополнительные блоки не наследуют фильтры основного.
Каталоги по базе и департаменту; единый выбор в интерфейсе. Общие файлы catalogs/<base_id>/<department_id>.json рядом с настройками на сетевой папке, схема и UTC-дата фактического чтения формы. Локальная копия для работы при сбое сети. Автообновление после чтения живой формы во время выгрузки, асинхронная публикация без ожидания SMB в очереди экспорта. При открытии админки проверяется сетевой кэш всех настроенных регионов. Если хотя бы один файл отсутствует/недоступен или старше 7 суток, надпись «Кэш устарел — обновите его самостоятельно». Ровно 7 суток ещё допустимы. Кнопка «Обновить» обходит все настроенные базы и департаменты; успешные частичные результаты сохраняются, недоступные области перечисляются. Основные статусы фиксированы по явному запросу пользователя. Недоступное поле/значение не удалять молча; показать ошибку конкретного задания.
Пустое поле или набор значений в дополнительном блоке — ошибка проверки перед публикацией. Предпросмотр количества заданий.

## Файлы

Настоящая системная Downloads/Выгрузка ОВЗИД для реестров ФССП/yyyy.mm.dd, одна папка на календарный день, повторный запуск использует ту же папку. Все файлы непосредственно внутри: «Департамент - Значение поля - Значение связанного поля.xlsx». Порядок полей из блока. Санитизация имён, разрешение коллизий без перезаписи, контроль длины. Отдельных подпапок/служебных файлов нет. Ноль записей — «Нет данных», файла нет.
Вторая кнопка впоследствии прочитает все выгрузки в выбранной папке и выполнит сопоставление по связке ключей. При существующей дневной папке показываются число корректных файлов из ожидаемых, список недостающих/повреждённых и три кнопки: «Перевыгрузить все», «Довыгрузить недостающие», «Отмена». Проверяются точное имя, структура XLSX и целостность ZIP-записей. Условия не извлекаются из данных книги: без служебного реестра доверяем именам файлов, сформированным приложением. Порядок заданий не влияет на сопоставление. Неоднозначные после очистки имена получают стабильный суффикс по ключу задания. При перевыгрузке старый файл заменяется только после полной проверки нового; при сбое остаётся старый. Посторонние файлы не удаляются. «Нет данных» не создаёт XLSX и проверяется при следующей довыгрузке снова. Старые тестовые папки с N не изменяются.

При подтверждённом пустом результате полной перевыгрузки прежний файл данного отбора удаляется: он больше не должен отдавать устаревшие строки будущим реестрам. Ошибка запроса или скачивания прежний файл не удаляет.

## Создание реестров — согласованный первый этап 29.10.2026

Счётчик чтения ОВЗИД накопительный для всего выбранного набора: заголовки и пустые строки не учитываются, при смене файла число не обнуляется. Обновление показывается при открытии следующего файла, каждые 2 000 строк общего чтения и после завершения каждого файла. Проверенные строки исходника считаются отдельно от прочитанных строк ОВЗИД.

Дополнение с уточнением заказчика: пятый файл «МесГГ_Возб_С_ДР_по_делу.xlsx» формируется по неизменному шаблону возбуждения только из строк, НЕ совпавших по исходному четырёхкомпонентному ключу с номером ИД. Среди этих строк ищется полное совпадение Должник/ФИО + Сумма долга/Переданная на принудительное исполнение сумма + Взыскатель + Номер дела. Регистр игнорируется только в ФИО. Наличие полного исходного совпадения исключает строку из пятого файла даже при отсутствующей, некорректной или конфликтующей ДР. Для оставшихся строк нужна единственная корректная ДР по делу; порядок и повторы сохраняются. Предыдущие реестры и базовая аналитика по номеру ИД не меняются. Выгрузки читаются один раз для двух ключей. Отдельный этап и счётчик по делу относятся только к дополнительным строкам. С учётом дополнительного окончания комплект из шести файлов публикуется целиком в новой подпапке.

Для тех же дополнительных строк создаётся шестой файл «МесГГ_Окон_С_ДР_по_делу.xlsx». Он использует неизменный шаблон окончания из 14 столбцов без столбца ДР. Два дополнительных файла имеют одинаковый состав исходных строк и отдельные цветные этапы. Комплект теперь состоит из шести файлов и публикуется целиком.

Вторая кнопка открывает выбор одного месяца (январь–декабрь), года, исходного XLSX и папки выгрузки ОВЗИД. Кнопка «ОК» доступна после выбора существующего исходника и папки. Период влияет только на имена файлов. Работа полностью локальная, вход в Пирамиду не требуется. Выгрузка и создание реестров одновременно не выполняются.

По уточнениям заказчика год отображается полностью в широком поле с переключением соседних лет. Месяцы представлены сеткой 4×3 крупных кнопок с выделенным выбранным месяцем и подписью периода. Папка выбирается современным диалогом Проводника с адресной строкой. Он сразу открывает системную Downloads/Выгрузка ОВЗИД для реестров ФССП. Диалог исходного файла открывается в заданной заказчиком сетевой папке реестров; её приватный путь передаётся при сборке через FSSP_REGISTRY_SOURCE_ROOT или registry_source_root в local/bootstrap.json.

Строгий ключ: Должник/ФИО (без учёта регистра), Номер ИД, Сумма долга/Переданная на принудительное исполнение сумма, Взыскатель. Остальной текст сравнивается без нормализации, числа Excel — без допуска. Повторы исходных строк и порядок сохраняются. Выгрузки читаются один раз; повреждение или отсутствие обязательных полей останавливает операцию.

По единственной корректной ДР точного совпадения создаются реестр возбуждения и реестр окончания. Остальные строки идут в реестр окончания без ДР. Машиночитаемые шаблоны встраиваются в EXE без изменения структуры: возбуждение — 11 столбцов с ДР, окончание — 14 столбцов без столбца ДР в обоих вариантах. Повторы выгрузки не размножают исходную строку. При разных непустых ДР дата не выбирается произвольно; строка остаётся без ДР с объяснением в аналитике.

Четвёртый файл — базовая аналитика: все исходные строки, «д.р.» и «Результат сопоставления». Неточные кандидаты не участвуют в формировании основных реестров; углублённая аналитика отложена по запросу заказчика.

Комплект сохраняется рядом с исходником в новой свободной подпапке «Сверка», «Сверка (1)», «Сверка (2)» и далее. Имена: Янв26_Возб_Изв_Отк_С_ДР.xlsx, Янв26_Окон_Изв_Отказы_С_ДР.xlsx, Янв26_Окон_Изв_Отк_БЕЗ_ДР.xlsx, Янв26_Аналитика.xlsx с выбранным периодом. До обработки проверяется полный путь с учётом номера подпапки, предел совместимости Excel — 218 символов. Если он превышен, пользователь получает понятное сообщение о необходимости сократить родительский путь; место и имена не меняются молча.

В главном окне снизу раскрывается независимая таблица этапов с заливкой состояния, как у выгрузки. Этапы: сверка («Проверено N/N, Найдено д.р. N», чтение файлов ОВЗИД показывается в той же строке), возбуждение с ДР, окончание с ДР, окончание без ДР, аналитика. Есть отмена и открытие результата. До публикации все этапы сохранения считаются подготовленными; статус «Сохранён» ставится только после успешной публикации всего комплекта. При ошибке/отмене предыдущие комплекты не затрагиваются, незавершённый новый комплект удаляется. Пустая категория создаёт книгу только с заголовком.

## Настройки и регионы

## Личные настройки и состав файлов — 30.10.2026

В админке два независимых переключателя: создавать аналитику; создавать оба дополнительных файла «по делу». По умолчанию оба включены, старые настройки сохраняют прежнее поведение. Три основных реестра создаются всегда. Отключённые выходы не записываются; их этапы имеют состояние «Пропущен» с серой заливкой, итог показывает фактическое число файлов. При отключённых файлах по делу соответствующее сопоставление не выполняется.

«Сохранить только для меня» сохраняет отдельный полный личный профиль в LOCALAPPDATA/FSSPReestrParser/personal-settings.json, не меняя общие настройки или их кэш. Личный профиль имеет приоритет до явного отказа от него. «Использовать общие настройки» удаляет только личный профиль и загружает общие/последнюю корректную общую копию. «Сохранить для всех» публикует текущие настройки по существующей проверке версии и после успешного сохранения отключает личный профиль текущего пользователя. Общий кэш и личный профиль никогда не подменяют друг друга. В админке видна текущая область действия; доступ к админке по-прежнему ограничен SID администратора.

## Запуск из Excel — 30.10.2026

Импортируемый модуль VBA и UserForm запускают приложение без ручного поиска EXE. Сначала проверяются зарегистрированный приложением путь и стандартная папка LOCALAPPDATA/FSSPReestrParser/app; доступны также EXE рядом с книгой, на рабочем столе и в Downloads. Если приложение найдено, оно запускается без скачивания и дальнейшее обновление выполняет само приложение.

При отсутствии приложения загрузчик получает последний стабильный выпуск GitHub chassehiboux/FSSPReestrParser, скачивает EXE и checksums.txt одного выпуска во временный файл и проверяет SHA-256 и PE x64 до установки. UserForm показывает этап, видимую полосу, процент, скачанные/общие МБ и скорость. Интерфейс остаётся доступным, есть отмена. Частичный файл не запускается, ошибка не повреждает существующий EXE. Установка не требует администратора. Поддерживаются VBA7 в Excel 32/64 бит на Windows 10/11 x64. При обычном запуске не требуется доступ к VBProject; он нужен только разработчику для сборки/импорта формы, если используется автоматический установщик компонентов.

Общие настройки — обычный JSON на согласованной сетевой папке FSSPReestrParser. Без криптографической подписи, без изменения ACL. Админ определяется учётной записью Windows (домен/SID); это ограничение интерфейса, не защита общего файла от ручной записи. Локальный кэш последней корректной версии. Ошибка сети — предупреждение и кэш; без кэша и общего файла показать ошибку. Снимок настроек фиксируется на весь запуск. Публикация через временный файл и переименование, контроль версии для предотвращения случайной потери чужого сохранения.
Региональные профили отдельно от баз: профиль ссылается на базы/департаменты/блоки. Сейчас один профиль Курган; при нескольких появляется выбор региона. Добавление баз не требует изменения очереди.

Публичный GitHub chassehiboux/FSSPReestrParser. На старте проверка стабильного релиза. При новой версии сообщение с ОК, затем прогресс, проверка целостности, установка отдельным процессом и перезапуск. При ошибке/недоступности разрешена работа на текущей исправной версии. Данные вне каталога версии. Запуск без прав администратора. Рабочие настройки/пароли/выгрузки вне публичного репозитория.
Пока приложение открыто, фоновая проверка каждые 30 минут. Новая версия вызывает системное уведомление и кнопку обновления. Активная выгрузка не прерывается. После завершения можно применить обновление; попытка новой выгрузки при известном обновлении сначала запускает обновление. При ошибке обновления снова разрешена работа.

## Уведомления

Системная область уведомлений Windows и значок приложения. После завершения: «Выгрузка завершена. Сохранено N из N. Ошибок N». Уже готовые файлы при довыгрузке входят в общий результат. При отсутствии данных добавляется их количество; отмена называется остановкой. Нажатие уведомления/значка возвращает окно приложения. Приложение можно свернуть и работать в других программах. Закрытие завершает процесс; фоновая проверка не устанавливает службу или автозапуск.

## Приёмка

Реальная форма трёх департаментов; вход, истёкшая сессия и контролируемые модели неверного пароля/сетевого сбоя без перебора паролей на производственном сервере. Контрольная выгрузка основного блока: следующее задание отправлено до завершения предыдущего; XLSX сохранён обработчиком очереди; нет потери быстрого события. Проверить отмену, пустые данные, HTML вместо Excel, коллизии имён, кеш настроек, неверный конфиг, обновление и восстановление после ошибки. Фактическое покрытие фиксировать отдельно, не объявлять непроверенное проверенным.

## Ключи элементов блоков

Единый раздел «Блоки» включает встроенный основной блок. Для каждого элемента (значения поля) настраиваются пары полей исходника и выгрузки и игнорирование регистра. Без настройки сохраняются четыре прежних ключа. В связанных условиях пары объединяются. Правила привязаны к файлам заданий; разные найденные даты рождения считаются конфликтом. Основной блок нельзя удалить. Личные и общие настройки сохраняют правила. Отдельная сверка распознаёт файлы по именам заданий выбранного региона, неизвестные файлы использует с прежним ключом.

## Сверка без взыскателя

Последнее уточнение отменяет нормализацию взыскателя: взыскатель полностью исключён из обоих ключей. Основной ключ — Должник/ФИО + Номер ИД + Сумма долга/Переданная на принудительное исполнение сумма. Дополнительный — те же поля с Номером дела вместо Номера ИД. Регистр игнорируется только в ФИО; номер и сумма сравниваются как раньше. Исходный взыскатель сохраняется в реестрах. Разные ДР по одному трёхкомпонентному ключу считаются конфликтом, подстановка даты не выполняется. Настройка ключей удалена, единый список блоков с основным сохранён; прежние настройки ключей из JSON игнорируются.

## Единые реестры для двух способов поиска

Сначала основной ключ Должник/ФИО + Номер ИД + Сумма. Только при отсутствии самого совпадения ключа выполняется дополнительный поиск: Должник/ФИО + Номер дела исходника/Номер ИД выгрузки + Сумма. Нет даты/конфликт/некорректная ДР при уже совпавшем основном ключе не разрешает подменять результат вторым поиском. Найденные обоими способами строки входят в одни основные реестры, остальные — в БЕЗ_ДР. Отдельных файлов по делу и их переключателя больше нет. Поиск вторым способом всегда включён, старый параметр отключения игнорируется. Аналитика сохраняет способ сопоставления. В основной блок добавляется «Реестры возврата ИД в ПУ» (15 заданий на три департамента). Возобновление старого pipeline с прежним набором статусов исключено версией правил в подписи запуска.
