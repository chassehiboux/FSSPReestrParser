# План реализации

## Инструкция

Для v0.3.10 заново экспортировать последний Word, сравнить страницы с вшитыми, проверить изменённые страницы и включить проверку выпусков каждую минуту. Собрать EXE и опубликовать после CI.

1. Подготовить обезличенные снимки реальных интерфейсов в демонстрационном окружении без отправки выгрузок.
2. Встроить семь утверждённых страниц Word как изображения без изменения текста и стрелок; добавить многостраничный диалог и отметку завершения для первого запуска.
3. Добавить кнопку слева сверху и отдельную инструкцию со снимками; проверить страницы и публикацию.

## Единый запуск

Восстановление входа: исключить ожидание пользователя из таймера авторизации, распознавать отказ без перезагрузки страницы, повторять подготовку задания при возврате на вход. Проверить длительный ввод, неверный пароль, повторный вход, отмену и сохранение уже выполненных заданий.

1. Добавить выделенный оркестратор с локальными снимками/состоянием, повтором неудачных выгрузок и отдельным подтверждением записи на целевой диск.
2. Научить формирование реестров сохранять результат в заранее выделенную папку, читать только подтверждённый список выгрузок и обрабатывать полностью пустой отбор.
3. Добавить общую кнопку, сворачиваемые отдельные операции, упрощённый выбор периода и смешанную таблицу всех этапов с продолжением.
4. Проверить потерю записи, повтор, восстановление после остановки, повреждённый файл, пустые отборы, длинный путь и неизменность отдельных операций. Собрать новый EXE.

## Устранение зависимости Excel от References

1. Заменить типизированный WinHTTP с событиями на встроенный Windows WinINet с порционным чтением и обновлением формы между порциями.
2. Собирать книгу без дополнительной ссылки и проверять импорт экспортированных компонентов в чистую `.xlam`.
3. Повторить сценарии скачивания, ошибки и отмены, обновить пакет и инструкцию.

## Настройки и загрузчик Excel

1. Добавить совместимые флаги выходных файлов и отдельное хранение личного профиля, тесты приоритета/сброса/публикации.
2. Связать переключатели и три действия сохранения с админкой; исключать отключённые выходы и помечать этапы пропущенными.
3. Реализовать модуль VBA, асинхронное скачивание и UserForm с процентами, МБ, скоростью, отменой и проверкой EXE.
4. Собрать импортируемые компоненты формы и пример запуска, проверить установленный/неустановленный сценарии, ошибку и отмену; собрать новый EXE и описать установку.

Исправление счётчика чтения: считать фактические непустые строки всех XLSX одним накопительным счётчиком, показывать его на границах файлов и проверить отсутствие сброса на наборе нескольких файлов.

Дополнение по номеру дела: индекс при том же чтении выгрузок → исключение всех строк с полным исходным совпадением по ИД (даже без ДР) → отдельный пятый реестр возбуждения для оставшихся совпадений по делу → этап и счётчик дополнительных строк → проверки пересечения, конфликтов ДР, неизменности прежних файлов и реальный прогон → сборка EXE.

1. Обследовать исходники PyramidReports и живую форму через сохранённый Chrome. Переносим правила, а не Python runtime. Новый Go runner необходим по прямому запросу самостоятельной архитектуры.
2. Проверить Go/Rod/Walk на сквозном прототипе с установленным браузером.
3. Разделить модули: model/config, Windows integration, browser/auth/form, queue/download, native UI/admin, releases/updater.
4. Реализовать основной блок, изоляцию контекстов, очередь 3, плоские файлы и прогресс.
5. Конструктор блоков, каталоги департаментов, публикация обычного JSON на SMB и кэш.
   Панель прогресса раскрывается внизу, состояния окрашены. Дневная папка поддерживает довыгрузку по проверенным именам XLSX. Общий кэш по областям устаревает после 7 суток, обновление ручное по всем настроенным базам и департаментам. Уведомления Windows и фоновая проверка релизов каждые 30 минут.
6. Подготовить публичный репозиторий и GitHub Actions для сборки. Настройки среды в локальном bootstrap, рабочие пути не публиковать.
7. Проверить обновление и перезапуск локально; выпустить первую сборку после проверок.

Сборка нового проекта отдельная: deploy_and_build.py PyramidReports не используется и не изменяется. Новые зависимости фиксируются go.mod/go.sum, устанавливаются в окружении. GUI манифест встраивается при сборке.

## Вторая кнопка — первый этап

2. Реализовать точный индекс, безопасное разрешение ДР и четыре выходных файла с сохранением типов и порядка строк.
3. Добавить диалог месяца/года/путей и встроенную таблицу пяти этапов с цветами, счётчиками и отменой.
4. Проверить граничные случаи и реальный комплект 940 / 940 / 2 436 / 3 376, собрать EXE для локальной проверки. Углублённый поиск неточных кандидатов отложить.

## Исправление запуска выгрузки и лимита

Убрать лишнюю подготовительную вкладку и повторную навигацию после выбора департамента, передавать подготовленную вкладку первому заданию. Разрешить 20 активных заданий в админке и проверке общих настроек. Проверить маршрутизацию, сохранение первого target/context, ошибки страницы и лимит очереди на 20 заданий, затем собрать исправленный EXE.

## Ключи элементов блоков

Добавить модель пар и правил элементов, редактор ключей в общем списке блоков, передачу правил файлов в общую и отдельную сверку, индексирование отдельно по каждому правилу и объединение результатов с проверкой конфликтов ДР. Проверить совместимость прежних настроек и сборку.

## Сверка без взыскателя

Восстановить фиксированную сверку, заменить оба ключа на три поля, убрать нормализацию взыскателя. Проверить сохранение исходного взыскателя, совпадение при его различии/пустоте, конфликт дат между разными взыскателями, неизменность ФИО/суммы/номеров. Собрать и проверить в CI.

## Единые реестры для двух способов поиска

Добавить пятый базовый статус; индексировать номер ИД выгрузки для обоих способов; объединить результат в основной Birthday и счётчики. Сократить файлы и этапы, убрать переключатель, сохранить только флаг аналитики. Проверить приоритет ИД, конфликты ДР, объединённые файлы и возобновление pipeline; собрать и выпустить релиз.

## Совпавшие строки с пустой ДР

Отделить подтверждённое совпадение с пустой ДР от отсутствия/конфликта сопоставления. Обновить отбор обоих основных реестров, БЕЗ_ДР и счётчики. Проверить точный и дополнительный поиск с пустыми ДР и защиту от конфликтов. Завершить анализ консервативных правил без их внедрения.
