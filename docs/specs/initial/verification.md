# Проверки первой версии

Дата: 29.10.2026. Среда: Windows x64, Go 1.27.3, установленный Google Chrome, реальная Курганская база.

## Реальная форма и выгрузка

- Проверены Курган 39, Курган-Восточный 43, Шадринск 40: по 57 полей в каждом каталоге.
- Живая форма использует числовые значения статусов 33, 100057, 100066, 100127; названия разрешаются по форме конкретного департамента. Сохранённый каталог PyramidReports содержал другой формат значений, поэтому его нельзя было переносить как константы запроса.
- Кнопка выгрузки находится по надписи «Выгрузить в Excel» в панели jqGrid; прежний селектор по title не соответствовал живому DOM.
- Отключена стандартная эмуляция Rod (Chrome 114/macOS); используется реальный браузер. Ожидание DOMContentLoaded соответствует поведению PyramidReports. Результат фильтра ждём по завершению AJAX, а не по случайному начальному отсутствию spinner.
- Контрольный основной блок: 12 из 12 XLSX сохранены, ошибок 0; очередь 10:56:45–11:05:04. Следующие задания отправлялись до первого скачивания. Размер 12 книг около 45 МБ. Это проверка интеграции, не замер чистой производительности.
- После изменения изоляции сессий выполнена дополнительная проверка: 3 независимых департамента, по одному файлу, все 3 сохранены. Прикладные cookies хранятся отдельно на пару база/департамент; между контекстами передаётся только SSO.
- Финальная дневная папка содержит 12 XLSX без служебных файлов. Для перехода на новую схему туда скопированы недостающие результаты полного контрольного запуска из прежней тестовой папки, с сохранением уже полученных новых результатов. Старые тестовые папки не изменялись.

## Автоматические проверки

- Основной блок 12, независимые и связанные комбинации, дедупликация, устойчивые имена после перестановки, коллизии имён.
- Одна дневная папка при конкурентном создании.
- Не более 3 активных заданий до сохранения; отмена всей очереди; повтор только конкретного задания при истечении входа.
- HTML вместо XLSX отклоняется; ZIP-записи проверяются на целостность; старый файл сохраняется при неудачной замене; существующие и недостающие файлы классифицируются отдельно.
- Локальный кэш настроек при недоступном/повреждённом общем файле; конфликт версии при публикации.
- Проверка администратора по SID текущего пользователя Windows.
- Порог кэша: ровно 7 дней допустимы, 8 дней — устарел; отсутствующая область отмечается отдельно; одинаковые ID департаментов разных баз не смешиваются.
- На локальной форме в реальном Chrome проверены неверный пароль, запрос повторного ввода, успешный повтор и сохранение через DPAPI, отмена без отправки, ошибка страницы вместо ложного «Нет данных». Неверные пароли на корпоративный сервер не отправлялись.
- Обновление: сравнение версий, новый релиз не скрывается предыдущей проверкой, отклонение неправильной SHA-256, проверка настоящего Windows PE x64. Отдельный процесс замены проверен локальным исполняемым пробником: замена, резервная копия, подтверждение запуска.

## Проверка собранного интерфейса

- Компактное главное окно и встроенная иконка.
- Панель снизу в том же окне; столбца «Блок» нет; проверены заливки подготовки и сохранённых файлов.
- Диалог дневной папки показал «Найдено 12 из 12», все три требуемые кнопки. «Довыгрузить недостающие» пропустило все готовые книги без запуска браузера; отображены 12 зелёных результатов.
- «Свернуть» вернуло компактный размер.
- Админка доступна текущему SID. Сетевой кэш прочитан: 3 актуальных департамента с датами. Проверен поиск поля «Статус» и отображение реальных значений конструктора; изменения рабочих блоков при проверке не публиковались.
- Общий кэш реально обновлён через движок по всем трём настроенным департаментам, сохранены отдельные JSON с UTC-временем и полями.
- Системное уведомление завершения вызывается после результата, используется Windows NotifyIcon. Фоновая проверка настроена на 30 минут; полный получасовой интервал вручную не выжидался.

## Ограничения покрытия

Исправлено явным UTF-8 для stdout/stderr сборщика и режимом `python -X utf8` в workflow. Исправление опубликовано отдельной версией без переназначения существующего тега.

Выпуск [v0.1.4](https://github.com/chassehiboux/FSSPReestrParser/releases/tag/v0.1.4) опубликован. [GitHub Actions](https://github.com/chassehiboux/FSSPReestrParser/actions/runs/40843392186) успешно выполнил проверки, сборку и публикацию. Локальная сборка также прошла при принудительной исходной кодировке консоли cp1252. Настоящий опубликованный EXE скачан через механизм обновления приложения: проверены SHA-256 и формат Windows PE x64. Размер 17 227 776 байт; SHA-256: `5d586142d4ebe21eead7d8585f729a1f0959981ae178ebe5131f80372d96cf1e`.

Первую версию проверяли на этом Windows-компьютере с Chrome. Отдельный чистый компьютер без инструментов разработчика и Edge отдельно не проверялись. Будущие региональные базы и алгоритм создания реестров не входят в первую версию. Возобновление опирается на ожидаемые имена и целостность XLSX, а не на доказательство бизнес-содержимого произвольно подложенной книги. Настройки головного скрытого режима, изменённые заказчиком для тестирования, не сбрасывались автоматически.
# Уточнение дополнительного отбора и окончание 29.10.2026

По уточнению заказчика в дополнительные реестры включаются только строки без совпадения исходного ключа с номером ИД. В индексе явно отмечается факт совпадения, независимо от результата поиска ДР. Автотест проверяет исключение строк при совпавшем исходном ключе с корректной, отсутствующей, некорректной и конфликтующей ДР, даже если по делу найдена корректная дата. Для дополнительных строк сформированы возбуждение и окончание по неизменным шаблонам. Проверены одинаковый состав, заголовки окончания, пустые дополнительные категории, повторы и остальные прежние сценарии. Тесты registry/ui и vet для этих пакетов прошли.

Реальный прогон на приватном контрольном наборе 12 выгрузок: 940 / 940 / 2 436 / 3 376 / 22 / 22 строк в шести файлах. Результат: локальная «Для теста/Сверка (4)». Независимая проверка openpyxl подтвердила отсутствие исходных совпадений среди 22 дополнительных строк, одинаковый состав обоих дополнительных файлов, 11 и 14 столбцов по шаблонам. Все значения прежних четырёх файлов совпадают с предыдущим контрольным комплектом «Сверка (3)». Собран EXE 0.1.8-dev в bin/case-extra; рабочие XLSX в Git не включены.

# Исправление первого открытия и лимита 29.10.2026

В getSession обнаружена лишняя последовательность: общая форма → переключение департамента → повторная общая форма → закрытие вкладки → новая вкладка в Begin. Убраны промежуточные открытия: новый контекст сразу выбирает нужный департамент, подготовленная вкладка передаётся первому Begin. Переключение после SSO выполняется только если сервис вернул другой департамент. Точная причина видимого заказчику сообщения error без сохранённой трассы не устанавливалась; убран подтверждённый лишний цикл, который мог обрывать стартовый запрос таблицы.

В настоящем Chrome на локальном HTTP-сервере проверены начальный маршрут, отсутствие дополнительного открытия формы первым Begin, готовый пустой результат задания, сохранение target, изоляция контекстов двух департаментов, новая вкладка следующего задания и обнаружение настоящей ошибки таблицы. Существующий тест неверного пароля, повторного ввода и отмены также прошёл. Реальное чтение формы Кургана через cmd/verify без выгрузки прошло: 57 полей, ошибок нет. Проверка повторной выгрузки на производственном сервере и одновременных 20 производственных запросов не выполнялась.

Лимит 12 был локальным ограничением формы и Validate, заменён общим MaxParallel=20. Проверены принятие 20 и отклонение 0/21. Тест очереди подтвердил запуск 20 заданий, ожидание 21-го до сохранения и освобождение всех слотов при отмене. Проверки browser/model/queue/ui и go vet ./... прошли. Собрана локальная версия 0.1.6-dev в bin/startup-fixed. Публикация релиза не выполнялась.
