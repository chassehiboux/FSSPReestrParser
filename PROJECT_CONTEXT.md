## Что согласовали с заказчиком

- Windows 10/11 x64, у пользователей уже есть Chrome либо Edge, доступ к GitHub и корпоративной сетевой папке. Всего примерно 10–20 пользователей, обычно одновременно работает один.
- Приложение запускается по необходимости. Лёгкая поставка одним EXE, без Python и отдельного Chromium у пользователя. Выбран Go + Rod + Walk, используется установленный браузер.
- Каждый входит в Пирамиду своим логином и паролем. Неверный пароль должен приводить к понятному повторному диалогу, сетевые ошибки нельзя выдавать за неверный пароль. Сохранение пароля добровольное, защита Windows DPAPI.
- Админка видна и доступна только учётной записи Windows заказчика dzuikevich, проверка по SID. Отдельно проверяется обработчик открытия. Это ограничение интерфейса, а не защита сетевого JSON от ручного редактирования.
- Все настройки общие через корпоративную SMB-папку. Заказчик явно отказался от подписи настроек и не может настраивать права общей папки. Не вводить подписи/ACL повторно без нового запроса.
- Настройки должны расширяться на другие базы, департаменты и региональные профили: например, Курганская база для Кургана, другая база для Тюмени. Пока настроен только Курган.
- Headless включён по умолчанию; переключатель только у администратора для тестов. Заказчик сам временно выключал headless в рабочих настройках: не сбрасывать его выбор автоматически.
- Прогресс не занимает главную форму до запуска. По последнему уточнению он раскрывается снизу в том же окне, увеличивая окно; для двух операций независимые панели. Отдельное окно прогресса было промежуточным решением и больше не нужно. Столбец «Блок» убран, состояния имеют цветовую заливку.

## Первая кнопка: выгрузка ОВЗИД

Последнее исправление запуска 29.10.2026: контекст сразу открывает маршрут выбранного департамента, без предварительной общей формы. Подготовленная вкладка остаётся открытой и используется первым Begin, затем каждое задание получает собственную вкладку в том же изолированном контексте департамента. Убран повторный переход на общую форму после выбора департамента. Это исправляет подтверждённый лишний цикл; точная причина ранее увиденного сообщения error без трассы не установлена. Реальное чтение Кургана без выгрузки подтвердило 57 полей. Локальный Chrome-тест проходит через полный первый Begin и проверяет маршруты, target, изоляцию и обнаружение ошибок. Лимит администратора теперь 1–20 (model.MaxParallel), исходное значение 3 не менялось. Проверено 20 активных слотов в тестовой очереди. Исправленный EXE: bin/startup-fixed/FSSPReestrParser-windows-amd64.exe, версия 0.1.6-dev; релиз не публиковался.

Рабочая форма: `https://kgn.pyramid.vostok-electra.ru/ovzid/status/all`. Фактические адреса баз и настройки среды хранятся в приватных рабочих конфигурациях, а не в исходниках публичного репозитория.

Основной неизменяемый блок: Курган (39), Курган-Восточный (43), Шадринск (40); поле «Статус», четыре значения:

- Направлены на исполнение (нет возбуждения)
- В исполнении (возбуждены ИП)
- ИД возвращенные из ФССП
- Подготовка ИД к возврату в ПУ

Итого 12 заданий. До 3 активны одновременно; слот занят до сохранения файла, ошибки, отмены либо подтверждённого отсутствия данных. Пока формируются предыдущие, запускаются следующие в пределах лимита. Лимит меняется в админке. Подписка на скачивание устанавливается до отправки запроса; сохранением занимается общая очередь.

Дополнительные блоки настраивает администратор: поля, несколько значений, текст по типу поля, добавление/удаление полей. Независимые поля дают отдельные задания по значениям, связанные — комбинации условий через И. Блоки объединяются, одинаковые задания удаляются. Основные фильтры не наследуются дополнительным блоком. Есть предпросмотр числа заданий.

### Сохранение и повторный запуск

Файлы непосредственно в системной папке Downloads:

```text
Выгрузка ОВЗИД для реестров ФССП\
  yyyy.mm.dd\
    Курган - Направлены на исполнение (нет возбуждения).xlsx
    Курган - В исполнении (возбуждены ИП).xlsx
    ...
```

Одна папка на день, без номера N, без дополнительных подпапок и служебного JSON. Для связанных условий значения перечисляются в имени через дефис. После очистки имён коллизии получают стабильный суффикс по ключу задания, чтобы не перезаписать другой отбор.

При повторном запуске диалог показывает найдено N из N, недостающие/повреждённые файлы и кнопки «Перевыгрузить все», «Довыгрузить недостающие», «Отмена». Проверяются ожидаемое имя, структура XLSX и целостность ZIP. Готовый файл заменяется только после проверки нового; ошибка сохраняет предыдущий. Посторонние файлы не удаляются. Подтверждённый пустой результат полной перевыгрузки удаляет устаревший файл данного отбора. «Нет данных» не создаёт файл, поэтому при следующей довыгрузке проверяется снова. Старые тестовые папки с N сохранены.

Без служебного реестра сопоставление доверяет именам созданных приложением файлов: произвольно подложенная корректная книга с ожидаемым именем не проверяется на бизнес-содержимое.

## Кэш и общие настройки

Обычный `settings.json` в согласованной корпоративной папке FSSPReestrParser. Полный реальный UNC-путь и SID доступны локально в игнорируемом `local/bootstrap.json`, а для CI — в GitHub Secrets `FSSP_SHARED_PATH` и `FSSP_ADMIN_SID`. Не выводить их целиком в публичные документы и не коммитить рабочие конфиги. Ориентир размещения — корпоративная папка заказчика в разделе Excel/ВЗИД/FSSPReestrParser.

Публикация настроек атомарная, с проверкой версии от потери параллельных сохранений. На весь запуск фиксируется снимок настроек. При недоступности общего файла используется последняя корректная локальная копия с предупреждением. Если нет ни общего файла, ни корректной копии, требуется восстановление настроек, а не молчаливое создание пустого профиля.

Кэш полей и значений общий, отдельный для каждой пары база/департамент: `catalogs/<base_id>/<department_id>.json` рядом с общими настройками. Есть схема и UTC-время чтения живой формы, локальная копия. Во время выгрузки прочитанные живые поля асинхронно публикуются в общий кэш. В админке отсутствие, недоступность либо возраст более 7 суток отмечается как устаревший кэш; ровно 7 суток ещё допустимы. Кнопка «Обновить» обходит все настроенные базы и департаменты. Частичные успехи сохраняются, ошибки перечисляются. Сейчас реально прочитано по 57 полей для каждого из трёх департаментов.

Локальные данные приложения: `%LOCALAPPDATA%\FSSPReestrParser` — кэш, каталоги, защищённые учётные данные и сессии. Выгрузки остаются в Downloads. Не публиковать пароли, cookies, browser storage, выгрузки.

## Уведомления и обновления

Значок Windows NotifyIcon и системное уведомление по завершении: «Выгрузка завершена. Сохранено N из N. Ошибок N»; также учитываются пустые результаты и отмена. Нажатие возвращает окно. Можно свернуть и заниматься другими делами.

Проверка стабильного GitHub Release при запуске и каждые 30 минут, пока приложение открыто. При найденном обновлении на старте пользователь нажимает ОК, затем прогресс загрузки, установка и перезапуск. Фоновая проверка показывает уведомление и кнопку обновления, не прерывает активную выгрузку. Следующая выгрузка при уже известном обновлении сначала предлагает применение. Ошибки/недоступность проверки или обновления позволяют работать на текущей версии. Службы и автозапуска нет.

Пакет проверяется по SHA-256 из checksums.txt и формату Windows PE AMD64. Отдельный процесс ждёт завершения основного, заменяет EXE с резервной копией и ждёт подтверждения запуска; при сбое восстанавливает старый. Скачивание имеет контекст до 5 минут, короткая проверка релиза — 25 секунд; нельзя возвращать ограничение всего скачивания 20 секундами.

Последнее уточнение: дополнительные возбуждение и окончание по номеру дела содержат ТОЛЬКО строки без совпадения исходного ключа с номером ИД. Проверяется сам факт совпадения, а не наличие найденной ДР; совпавшие строки без/с конфликтом ДР также исключаются. На контрольных 12 выгрузках оба дополнительных файла содержат по 22 строки, комплект из шести файлов проверен в «Для теста/Сверка (4)». Все значения прежних четырёх файлов совпали с прошлым контрольным комплектом. Текущий EXE — bin/total-counter/FSSPReestrParser-windows-amd64.exe, версия 0.1.9-dev.

29.10.2026 заказчик разрешил реализацию основных реестров с базовой аналитикой; расширенный поиск кандидатов отложен. Реализация: internal/registry, встроенные неизменные шаблоны internal/registry/templates, диалог internal/ui/registers.go, современный выбор папки internal/platform/folder_dialog.go.

Выбор одного месяца сеткой крупных кнопок, широкое поле года, два диалога выбора. Исходный файл открывается из заданной заказчиком сетевой папки: приватный путь хранится в local/bootstrap.json, ключ registry_source_root, и встраивается build.py. Для CI добавлены переменная и секрет GitHub FSSP_REGISTRY_SOURCE_ROOT, значение уже настроено. Диалог папки использует IFileOpenDialog с адресной строкой и сразу открывает системную Downloads/Выгрузка ОВЗИД для реестров ФССП.

Точный ключ: Должник/ФИО без учёта регистра, Номер ИД, Сумма долга/Переданная на принудительное исполнение сумма, Взыскатель. Остальной текст не нормализуется. Строки исходника и их повторы сохраняются. ДР используется только при единственной корректной дате. При отсутствии или конфликте ДР строка остаётся без ДР, причина попадает в аналитику. Машиночитаемый шаблон окончания менять запрещено: оба окончания имеют 14 столбцов без ДР. Возбуждение имеет 11 столбцов с ДР.

Создаются шесть XLSX с префиксом выбранного месяца/года. Дополнительный пятый файл — «Возб_С_ДР_по_делу.xlsx» по тому же неизменному шаблону возбуждения. Для него используется независимый ключ Должник/ФИО + Сумма долга/Переданная на принудительное исполнение сумма + Взыскатель + Номер дела. По уточнению заказчика включаются ТОЛЬКО строки без полного совпадения по исходному ключу с номером ИД. Наличие исходного совпадения исключает строку даже при отсутствующей, некорректной или конфликтующей ДР. По этим же дополнительным строкам создаётся шестой файл «Окон_С_ДР_по_делу.xlsx» по неизменному 14-столбцовому шаблону окончания без столбца ДР. Номер ИД не проверяется и не заменяется в исходных значениях. Учитывается только одна корректная ДР, конфликты исключаются. Три основных реестра и базовая аналитика по ИД не меняются. Оба ключа обрабатываются при одном чтении выгрузок, счётчики раздельные. Результаты рядом с исходником в новой свободной подпапке «Сверка», «Сверка (1)», «Сверка (2)» и далее. Существующие комплекты не изменяются. При полном пути более 218 символов, включая номер подпапки, запуск отклоняется с предложением сократить родительский путь. Для исходного длинного сетевого примера первая папка укладывается, номерные могут превышать предел; автоматическое сокращение имён не согласовано.

Панель в главном окне показывает семь этапов с цветными состояниями: сверка со счётчиками, возбуждение с ДР, окончание с ДР, окончание без ДР, аналитика и дополнительные возбуждение с ДР и окончание по номеру дела. Есть отмена, уведомление и открытие папки. Выгрузка и создание реестров одновременно не выполняются. Комплект сначала формируется и проверяется во временной папке; ошибка и отмена убирают только собственную незавершённую новую папку. Текущая сборка с сопоставлением по делу — bin/total-counter/FSSPReestrParser-windows-amd64.exe, версия 0.1.9-dev.

Реальный прогон Go-обработчика на 12 выгрузках: 3 376 строк, найдено 940 ДР; файлы содержат 940 / 940 / 2 436 / 3 376 строк. Успешный комплект находится локально в «Для теста/Сверка (1)». Базовая аналитика имеет только исходные столбцы, д.р. и результат. Предварительная расширенная аналитика из обследования остаётся в «Для теста/Сверка», её алгоритм не является реализованной частью приложения. ### Что важно не сломать при работе с Пирамидой

- В форме имя поля каталога `CaseStatusName`, фактический фильтр `CaseStatus_StatusName`. Числовые ID четырёх статусов при обследовании: 33, 100057, 100066, 100127. Значения разрешаются через живую форму департамента; старый кэш PyramidReports имел другой формат и не подходит как константа запроса.
- У кнопки выгрузки не было ожидаемого title. Поиск по тексту «Выгрузить в Excel» в `.ui-pg-button-text` и ближайшему элементу с ролью button.
- Стандартная эмуляция Rod Chrome 114/macOS отключена через `NoDefaultDevice()`, используется установленный браузер.
- Ожидается DOMContentLoaded, затем завершение AJAX загрузки таблицы. Нельзя считать начальное отсутствие spinner доказательством готовности или ошибку страницы — пустым результатом.
- Контексты и прикладные cookies изолированы по базе/департаменту; передаётся только SSO. `/login/department/...` — штатный маршрут, не признак истёкшей сессии.
- При настоящей потере входа конкретное задание восстанавливает авторизацию и повторяется один раз, сохраняя слот. Неверный пароль вызывает диалог, отмена отменяет всю операцию.
- Подписка скачивания до запроса. После запланированной отправки выгрузки не обращаться к DOM вкладки, которая уже переходит на ответ. Каталог временных скачиваний — абсолютный путь.
- HTTP/HTML/сетевые ошибки отличать от Excel; ERR_ABORTED при нормальном начале download не считать ошибкой. Закрытие target обрабатывать. Завершённый успех нельзя перезаписать поздней ошибкой.

## Сборка и проверка

Go 1.26+ по go.mod, на этом компьютере установлен Go 1.27.3 в `.tools/go/bin/go.exe`. Python 3.13 нужен только для build.py. Runtime: Rod, Walk, Windows API; зависимости зафиксированы в go.mod/go.sum, CGO не требуется. `rsrc` v0.10.2 нужен при сборке для ресурсов. Новые зависимости не добавлять без объяснения необходимости.

Из корня проекта, если Go не находится через PATH:

```powershell
.\.tools\go\bin\go.exe test ./...
.\.tools\go\bin\go.exe vet ./...
python -X utf8 build.py --version 0.1.4 --output-dir bin/next
```

build.py читает приватный `local/bootstrap.json` либо переменные FSSP_SHARED_PATH/FSSP_ADMIN_SID; EXE и checksums.txt попадают в выбранный output-dir. Отдельная папка удобна, если прежний EXE запущен. Для локальных браузерных тестов авторизации перед `go test ./internal/browser -v` задаётся `$env:FSSP_BROWSER_TESTS = '1'`. Эти тесты используют локальную модель страницы, не перебирают неверные пароли на рабочем сайте.

`cmd/verify` без `-export` обновляет каталог; `-export` явно включает настоящую выгрузку. Перед применением посмотреть текущие флаги в исходнике. Игнорируемая `local/` содержит вспомогательные диагностические сценарии и пробники предыдущей работы, но не является обязательной частью продукта. Не коммитить её содержимое или приватное состояние браузера.

Сборка независима от PyramidReports: `deploy_and_build.py` не используется, его режим 1 не требуется. При изменении программы нужен новый EXE/релиз нового проекта.
