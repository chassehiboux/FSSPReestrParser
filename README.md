# FSSPReestrParser

Главное окно компактное; при запуске оно расширяется вправо и показывает встроенную панель статусов рядом с кнопками. Подробности занимают оставшуюся доступную ширину экрана. Текущие 20 этапов помещаются в таблице на обычном мониторе; при меньшей рабочей области или большем числе строк доступна прокрутка. В общем запуске каждая скачанная выгрузка сразу сохраняется в «Исх.», после проверки записи локальная копия удаляется. Только неуспешно сохранённые книги остаются локально для продолжения.

Самостоятельное Windows-приложение для выгрузки ОВЗИД и последующего создания реестров ФССП.

Для продолжения разработки в новом чате: [контекст проекта](PROJECT_CONTEXT.md) — согласованные решения, архитектура, проверки, выпуск и ограничения.

## Пользователю

Windows 10/11 x64, установленный Chrome или Microsoft Edge, доступ к рабочей сети и GitHub. Python, Go и отдельный Chromium устанавливать не требуется.

Скачайте EXE из Releases и сохраните в локальной папке с правом записи (например, в папке пользователя). Запустите файл. При наличии обновления нажмите ОК: программа скачает новую версию и перезапустится. Если обновление недоступно, разрешена работа на текущей версии.

Нажмите «Выгрузить ОВЗИД и создать реестры», выберите исходный XLSX в сетевой папке исходников, затем месяц и год. При необходимости введите те же логин и пароль, что и при входе в Windows; префикс `vostok\` в логине не нужен. Пароль можно сохранить на этом компьютере; он защищается Windows DPAPI.

Программа выгрузит все настроенные отборы, проверит сохранение и создаст реестры. Рядом с исходником появится новая папка «Сверка», «Сверка (1)» и далее: внутри неё реестры и подпапка «Исх.» с выгрузками, без папки даты. В Windows конечная точка в имени папки автоматически убирается: в Проводнике она отображается как «Исх». При ошибке повторяются только неудачные задания или запись уже скачанного файла. Пока комплект неполный, сверка не начинается. Кнопка «Продолжить» возобновляет незавершённый запуск с сохранёнными локальными копиями. После перезапуска программы выберите тот же исходник, период и настройки для продолжения.

Прежние действия находятся в раскрываемом разделе «Отдельные операции». Описанный ниже дневной каталог Downloads используется только отдельной выгрузкой.

После нажатия кнопки окно расширяется вниз и показывает панель прогресса выбранной операции. Ячейки состояний окрашены. Кнопка «Свернуть» не прерывает операцию.

Основной профиль: Курган, Курган-Восточный, Шадринск; четыре заданных статуса. До 3 активных заданий. Результат — системная Downloads/Выгрузка ОВЗИД для реестров ФССП/yyyy.mm.dd. Все XLSX лежат непосредственно в этой папке. При отсутствии данных файл не создаётся. Служебных файлов в выгрузке нет. При повторном запуске за тот же день показываются найденные и недостающие файлы, предлагаются «Перевыгрузить все», «Довыгрузить недостающие», «Отмена». Готовые файлы проверяются по имени и целостности XLSX. Старые результаты заменяются только после успешного получения новых; посторонние файлы сохраняются. Отборы без данных проверяются повторно.

«Создать реестры возбуждения и окончания» открывает календарь месяцев, выбор года, исходного XLSX и папки выгрузок. Строгая сверка по ФИО, номеру ИД, сумме и взыскателю создаёт три основных реестра по встроенным шаблонам и базовую аналитику. Для строк без полного совпадения по исходному ключу дополнительно ищется ДР по ФИО + сумме + взыскателю + номеру дела. По найденным дополнительным строкам создаются ещё два файла: возбуждение с ДР и окончание по неизменному шаблону без столбца ДР. Всего шесть файлов. Совпавший исходный ключ исключает строку из дополнительных файлов даже при отсутствующей или конфликтующей ДР. Регистр игнорируется только в ФИО. Результаты сохраняются рядом с исходником в новую подпапку «Сверка», «Сверка (1)» и далее. Этапы, раздельные счётчики по ИД/делу и цветные состояния показаны снизу главного окна. Путь результата ограничен 218 символами для совместимости с Excel. Расширенный поиск неточных кандидатов пока отложен.

После завершения появляется системное уведомление «Выгрузка завершена. Сохранено N из N. Ошибок N». Программу можно свернуть; значок в области уведомлений и нажатие уведомления возвращают её окно. Пока программа открыта, новые версии проверяются также каждые 30 минут. Фоновое обновление не прерывает выгрузку.

## Администрирование

Кнопка доступна корпоративной учётной записи Windows, SID которой указан при сборке. Админ может обновить поля из Пирамиды, добавить дополнительные блоки, выбрать значения и режим связывания, изменить headless и сохранить настройки для всех.

Независимые поля: отдельное задание на каждое значение. Связанные поля: отдельное задание на каждую комбинацию; условия связаны через И. Основной блок всегда включён. Повторяющиеся одинаковые задания объединяются.

Настройки — обычный JSON на SMB без подписи по решению заказчика. Ограничение админки не запрещает ручное изменение файла при наличии доступа к папке. При недоступности SMB используется последняя корректная локальная копия с предупреждением. Удаление или повреждение общего файла при отсутствии кэша требует восстановления администратором. Локальные копии каталогов, кэш, защищённые сессии и учётные данные находятся в `%LOCALAPPDATA%/FSSPReestrParser`.

Региональные профили отдельно от баз; если опубликовано несколько профилей, появляется выбор региона. Адреса баз, рабочие сетевые пути и настройки в публичный репозиторий не включаются.

Общий кэш полей и значений хранится рядом с общими настройками в `catalogs/<base_id>/<department_id>.json`. В каждом файле дата чтения живой формы. В админке кэш старше 7 суток или отсутствующий отмечается как устаревший. Кнопка «Обновить» обходит все настроенные базы и департаменты, сохраняя успешные результаты при частичной недоступности. Есть локальная копия; перед выгрузкой допустимость условий всё равно проверяется на сайте.

## Разработчику

Go 1.26+ (проверено на 1.27.3), Python 3.13 для сборочного сценария. Сборка без CGO. Runtime-зависимости: Rod, Walk и Windows API. `rsrc` используется только при сборке для встраивания манифеста.

```powershell
go mod download
go test ./...
go vet ./...
$env:FSSP_SHARED_PATH = '\\server\share\settings.json'
$env:FSSP_ADMIN_SID = 'SID корпоративного администратора'
python build.py --version 0.1.0
```

Либо создайте игнорируемый `local/bootstrap.json` с полями `shared_settings` и `admin_sid`. Начальная сетевая папка исходных реестров задаётся приватным полем `registry_source_root` либо переменной `FSSP_REGISTRY_SOURCE_ROOT`; в GitHub Actions используется одноимённый секрет. Для сборки рядом с уже запущенным EXE используйте `--output-dir bin/next`. Работа с XLSX использует Excelize, пользователь получает один EXE без установки Excel-библиотек или Python.

Для браузерной проверки авторизации на локальной форме:

```powershell
$env:FSSP_BROWSER_TESTS = '1'
go test ./internal/browser -v
```

Утилита `cmd/verify` проверяет реальный движок без GUI. Параметр `-export` явно включает настоящую выгрузку; без него только обновляется каталог. Состояние браузера и рабочие настройки хранить только в `local/`, не коммитить.

GitHub Actions собирает выпуск по тегу `vX.Y.Z`; секреты репозитория `FSSP_SHARED_PATH` и `FSSP_ADMIN_SID` задаёт владелец. В выпуске EXE и checksums.txt. На обновлении проверяются источник, SHA-256 и формат Windows x64; замена выполняется отдельным процессом с резервной копией и подтверждением запуска.

Сборка полностью отдельная от PyramidReports. Его deploy_and_build.py не используется.

Согласованные требования и результаты проверок: `docs/specs/initial/`.
